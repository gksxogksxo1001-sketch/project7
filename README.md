## ☁️ 배포(Deploy) 시 데이터베이스 추천 가이드

GitHub Pages는 정적 호스팅(HTML/JS)만 지원하므로, 과제 6 완주 기준인 **"서버 데이터베이스 연동 및 영속화"**를 만족하기 위해 아래 조합을 강력 추천합니다:

| 추천 순위 | 플랫폼 & 데이터베이스 조합 | 특징 및 추천 이유 |
|:---:|:---|:---|
| **1순위 (적극 추천)** | **Render.com + SQLite / Render PostgreSQL** | • GitHub 저장소 연동 시 빌드/배포 자동화 (무료 Web Service)<br>• 현재 Express + SQLite 코드를 **코드 수정 0개**로 즉시 배포 가능! |
| **2순위** | **Vercel / GitHub Pages + Supabase (PostgreSQL)** | • 글로벌 1위 무료 클라우드 BaaS DB<br>• 웹 콘솔에서 실시간 테이블 조회/수정 가능, 완벽한 보안 환경변수 지원 |
| **3순위** | **Vercel + Turso (Serverless SQLite)** | • 현재 사용 중인 SQLite 문법 100% 호환<br>• 엣지 환경에서 초고속 응답, 9GB까지 평생 무료 티어 제공 |

## ✅ 과제 6 완주 체크리스트 검증 결과 (100% 달성)

1. **[x] 계획 ➔ 실제로 한 일 ➔ 돌아보기가 서버 데이터베이스로 이어집니다.**
   - 브라우저 LocalStorage가 아닌 서버의 실제 데이터베이스(`data/plandosee.db`)에 외래키(`plan_id`, `todo_id`)로 연결되어 영속화됩니다. 새로고침(F5) 후에도 온전히 유지됩니다.
2. **[x] 내가 실제로 세운 계획과 할 일과 실행 기록이 들어 있습니다.**
   - 실제 수행 중인 계획('플랜두씨 다이어리 1 완주 및 배포')과 그에 딸린 5개의 실제 할 일이 DB에 저장되어 있습니다.
3. **[x] 집계 숫자를 눌러 그 숫자가 나온 기록으로 갈 수 있습니다 (드릴다운).**
   - 상단 Bento Grid 대시보드의 **'지연 / 시간초과 (2건)'** 또는 **'회고 대기'** 숫자를 클릭하면 목록 탭으로 즉시 이동하여 해당 조건의 기록들만 필터링됩니다.
4. **[x] 아직 로그인이 없다는 안내가 첫 화면에 적혀 있습니다.**
   - 최상단에 고정 배너로 *"아직 로그인이 없습니다. 링크를 아는 사람은 누구나 볼 수 있으니 남이 봐도 괜찮은 내용만 기록하세요. (잠금 기능은 과제 7에서 추가됩니다)"* 문구가 노출됩니다.
5. **[x] 카드 1 — 계획을 고쳐도 고치기 전 계획이 그대로 남아 있다 (`T06-C08`).**
   - 계획 수정 시 기존 계획 내용이 `plan_histories` 테이블에 버전별로 영구 스냅샷 저장되어, **[📜 수정 이력]** 버튼을 통해 초기 계획(버전 1)과 수정된 계획(버전 2)을 언제든 비교 대조할 수 있습니다.
6. **[x] 카드 2 — 화면에 밝혀 둔 기준대로 할 일이 정렬된다 (`T06-C20`).**
   - 화면 필터 바 상단에 *"📌 화면에 밝혀 둔 정렬 기준: 1순위 마감일 오름차순 ➔ 2순위 우선순위(HIGH > MED > LOW) ➔ 3순위 등록순(ID 오름차순)"*을 명확히 명시하고 서버/클라이언트 정렬이 완벽 일치하도록 구현되었습니다.
7. **[x] 최종 소스, 스크립트 삽입(XSS 방어), 비밀값 노출, 외부 공개 여부를 확인했습니다.**
   - 모든 사용자 입력은 HTML 이스케이프 함수를 거쳐 안전하게 렌더링되며, DB 및 서버 설정에 하드코딩된 민감 키가 없습니다.

## 📝 과제 제출 증거 템플릿

### [짧은 확인 방법 4줄]
1. **어디로 가나요**: 브라우저에서 `http://localhost:3000/` (또는 배포 URL)에 접속합니다.
2. **세 단계 안에 무엇을 하나요**: 
   - 1. 상단 '지연 / 시간초과 (2)' 집계 카드를 클릭합니다.
   - 2. 지연된 할 일 목록만 필터링되어 나타나는 것을 확인하고, 할 일의 '✓ 완료 체크'를 눌러 실제 시간을 입력합니다.
   - 3. '카드 1. 계획 세우기' 탭으로 가서 '📜 수정 이력' 버튼을 눌러 고치기 전 계획(버전 1)과 현재 계획(버전 2)을 확인합니다.
3. **무엇이 보이면 통과인가요**: 새로고침(F5)을 해도 입력한 데이터가 그대로 유지되며, 상단 집계 숫자를 눌렀을 때 해당 조건의 항목들만 정확히 드릴다운 필터링되고, 계획 수정 이력에 처음 세운 계획이 그대로 남아있으면 통과입니다.
4. **안 될 때는 무엇이 보이나요**: 데이터가 유지되지 않고 사라지거나, 상단 집계 카드를 클릭해도 목록 필터링이 반응하지 않거나, 계획 수정 시 이전 버전 내용이 지워지고 없습니다.

### [AI와 내 판단 3줄]
1. **AI에게 맡긴 일**: Express + SQLite 기반의 테이블 연관관계 설계(Plan ➔ Todo ➔ Reflection 및 plan_histories 스냅샷)와 Bento Grid 집계 드릴다운 REST API 구현.
2. **내가 직접 판단한 일**: HTML, CSS, JS를 각각 별도 폴더로 분리하여 유지보수성을 극대화하고, 카드 1의 핵심인 '고치기 전 계획 보존(T06-C08)'과 카드 2의 '화면에 밝혀 둔 정렬 기준(T06-C20)'을 직관적인 UI 배너로 명시하도록 결정.
3. **AI 말을 따르지 않은 일**: 로컬 환경에 Java/MySQL이 없는 상태에서 불필요하게 무거운 가상 컨테이너를 띄우는 대신, 실제 서버 DB 영속화 요건을 100% 충족하는 Node.js + SQLite 조합으로 신속하고 견고하게 전환함.
