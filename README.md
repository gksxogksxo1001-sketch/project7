## 📝 과제 제출 증거 템플릿

### [짧은 확인 방법 4줄]
1. **어디로 가나요**: 브라우저에서 배포 주소 `https://gksxogksxo1001-sketch.github.io/projetct6/` (또는 로컬 `http://localhost:3000/`)로 접속합니다.
2. **세 단계 안에 무엇을 하나요**: 
   - 1. 상단 대시보드에서 **'지연 수 (T06-C30)'** 또는 **'막힘 수 (T06-C31)'** 카드를 클릭하여 해당 기록으로 드릴다운 이동합니다.
   - 2. 할 일 카드에서 **'✓ 완료 & 실행기록 적기'**를 눌러 시작시각, 끝난시각, 실제시간, 막힌이유를 적고 완료 처리합니다.
   - 3. **'카드 4. 돌아보기 & 다음 계획으로'** 탭으로 가서 회고의 **[🚀 이 고칠 점으로 새 계획 세우기]** 버튼을 눌러 고칠 점(T06-C33)이 새 계획 폼에 채워지는 것을 확인합니다.
3. **무엇이 보이면 통과인가요**: 새로고침(F5)을 해도 입력한 데이터와 집계 숫자가 유지되며, 집계 숫자를 누르면 해당 조건의 기록만 필터링되고, 상단 [📥 자료 내보내기 (JSON)] 클릭 시 백업 파일이 정상 다운로드되면 통과입니다.
4. **안 될 때는 무엇이 보이나요**: 새로고침 시 데이터가 초기화되거나, 완료 버튼을 연타했을 때 중복 기록이 쌓이거나, 집계 숫자를 눌러도 목록 필터링이 반응하지 않습니다.

### [AI와 내 판단 3줄]
1. **AI에게 맡긴 일**: 카드 3의 실행 기록 분리 스키마(`executions`) 설계, 완료 연타 멱등성 제약조건(`UNIQUE(todo_id)`), 및 카드 4의 집계 공식(T06-C28~C32) 구현.
2. **내가 직접 판단한 일**: 카드 5의 `contracts/pds-schema-v2.json` 스펙을 사전에 엄격히 정의하고, 돌아보기의 고칠 점이 다음 계획으로 자연스럽게 넘어가는 원클릭 연계 UX(T06-C33) 및 JSON 파일 내보내기 기능(T06-C36)을 채택.
3. **AI 말을 따르지 않은 일**: 외부 유료 클라우드 의존성 대신 로컬 SQLite 서버 DB와 GitHub Pages 오프라인 하이브리드 아키텍처를 결합하여, 서버 환경과 정적 웹 배포 환경 양쪽에서 100% 동일한 경험을 제공하도록 결정.
